## 0. 背景与目标

P8 负责把拼图游戏页从占位页替换为可玩的正式页面。P0–P7 已经完成核心逻辑、数据层和共享 UI 基础，P8-1 开始进行页面组装。

当前 `puzzle-game/puzzle.html` 已替换为正式游戏页，P8-1～P8-3 已接入页面骨架、输入/session、统计、保存与重玩，P8-4a-0 已把分组模型切换为事件级 90 组，P8-4a 已接通分组弹框与观察阶段切换；P8-4b 已新增独立设置页与 `site.v1.preferences`（详见 `docs/SETTINGS_PAGE.md`），P8-5 光标/极简 UI/移动端、P8-6 E2E 仍待完成。旧版游戏页布局保存在 `pre-refactor-2026-10` 基线中，只作为行为参考：

- 旧版同样是三栏：左侧参数，中间棋盘，右侧计时和统计。
- 旧版视觉偏普通网页，按钮和面板层级比较平。
- 本次重构保留三栏思路，但重新分配比例、留白和控件形态，让页面更像一个专注玩的小游戏。

P8 的总体目标：

- 桌面端优先，先确定三栏结构和交互，再补移动端。
- 保持轻量：不引入 Vue/React、不使用运行时图标 CDN、不引入新的 UI 依赖。
- 先做静态骨架和布局，再逐项接入输入、session、保存、设置和可访问性。
- 每一步都可以独立构建、验证和回滚。

## 1. 设计原则

1. **棋盘是主角**：中间棋盘占据最大视觉面积，左右两栏为它服务。
2. **三栏 3:4:3，内容向棋盘聚拢**：左菜单、中棋盘、右统计按 `3fr 4fr 3fr` 分配；页面四周保留 padding，左右两栏各自纵向居中，左栏右对齐，右栏以时间和统计为锚点对齐，让控件环绕棋盘而不是散在页面两侧。
3. **扁平、清新、简约**：不使用渐变、不强依赖卡片阴影；用留白、字号、字重和少量细线分层。
4. **按钮是浅灰浮起**：浅灰固体面、1px 边框、顶部细白色高光和轻阴影；按下时整体向中心缩小，不使用渐变或硬底边。
5. **按钮默认只用图标**：图标统一维护在 `src/shared/icons/sprite.svg`，页面用 `<use href="#icon-...">` 引用；游戏页图标已全部迁移。详见 `docs/ICONS.md`。
6. **参数用气泡弹框选择**：阶数、游戏模式、操作模式、分组都在按钮旁边弹出聊天气泡式弹框，选中项高亮。
7. **渐进接入**：P8-1 先渲染完整 UI，按钮不绑定业务事件；P8-2 开始逐个接入。

## 2. 页面状态

| 状态           | 左菜单                         | 棋盘                             | 右统计 / 操作                         |
| -------------- | ------------------------------ | -------------------------------- | ------------------------------------- |
| `observing`    | 当前阶数、模式、操作模式、分组可查看/切换 | 已打乱，可观察            | 计时 0；步数/TPS 初始；ao5/ao12 历史  |
| `running`      | 可切换阶数/模式/操作模式；分组锁定，切换参数后丢弃当前局 | 可移动        | 计时/步数/TPS 实时更新                |
| `blind` 运行中 | 模式图标显示盲玩               | 首次移动后隐藏数字               | 计时包含观察时间                      |
| 重玩中         | 阶数/游戏模式锁定，操作模式可切换 | 使用原打乱                     | 隐藏 ao；TPS 下方显示退出图标和“重玩中”标签 |
| `solved`       | 参数和分组可重新选择（分组只影响下一局） | 棋盘锁定，完成盘面               | 显示最终时间/步数/TPS；ao5/ao12 更新   |
| 保存中         | 当前参数冻结                   | 完成盘面保持                     | 显示保存状态；禁止新局                |
| 保存失败       | 当前参数恢复                   | 完成盘面保持                     | 常驻提示，允许重试保存                |
| 重玩加载中     | 参数保持                       | loading 占位                     | 显示加载状态                          |
| 存储错误       | 参数保持                       | 继续显示当前盘面                 | 非阻塞提示，允许重试                  |

P8-1 只实现“已复原预览”的静态骨架；P8-2 已接入 `observing` / `running` 和复原后的冻结，P8-3 已接入保存、重玩、完整结算和重玩状态栏。

分组按事件划分：事件 = 阶数 + 游戏模式，共 18 个；每个事件固定 5 个分组。游戏页只显示当前事件的 5 个分组，运行中禁用切换；完成后保存结束即可选择下一局的分组；分组管理和成绩列表见 `docs/PUZZLE_SCORE_PAGE.md`。

## 3. 信息架构

### 3.1 桌面三栏

```text
┌────────────────┬──────────────────────┬──────────────────┐
│           4×4  │                      │ 12.34            │
│   [阶][模][操] │        棋盘          │ 步数        28   │
│     [设][主]   │                      │ TPS       2.27   │
│                │         [↻]          │ ao5      11.82   │
│                │                      │ ao12     12.07   │
│                │                      │ [列表] [分组1]   │
└────────────────┴──────────────────────┴──────────────────┘
       3fr                 4fr                   3fr
```

- 页面四边使用统一 padding，左右大于上下，避免界面贴边。
- 左右两栏的整体内容纵向居中；左栏元素右对齐，右栏元素左对齐，贴近棋盘两侧。
- 三栏之间保留较大间距（约为上一轮的 2 倍），让左右内容环绕棋盘但不贴住棋盘。
- 棋盘不套额外底板或边框，和页面背景融为一体；保持正方形，宽度同时受中栏宽度和视口高度限制。
- 桌面端优先保证一屏内完成主要操作，不出现不必要的纵向滚动。

### 3.2 左栏：菜单

1. 顶部显示当前阶数，例如 `4×4`，使用等宽数字，字号至少与右侧时间同级。
2. 下方按钮分两行：
   - 第一行：阶数切换、游戏模式切换、操作模式切换；
   - 第二行：设置、回到主页，靠右对齐。
3. 左栏整体纵向居中，所有元素右对齐，和棋盘之间保留较大间距。
4. 阶数、游戏模式、操作模式点击后在按钮右侧弹出聊天气泡式弹框。
5. 设置按钮在 P8-4b 改为跳转独立设置页；P8-1 只保留按钮和标题。
6. 回到主页按钮使用同尺寸图标按钮，直接链接到 `/`。

### 3.3 中栏：棋盘

- 只放棋盘和棋盘下方的刷新按钮，不叠加计时或说明文字。
- 棋盘不套额外底板或边框，空白色和格子间隙直接露出页面背景，和整体背景融为一体。
- “棋盘 + 刷新按钮”作为一组整体下移，棋盘接近页面中心，刷新按钮在下方留出更大间距。
- 刷新按钮是透明底圆形图标按钮，居中放在棋盘下方；悬停显示浅灰圆底，按下缩小。
- 阶数范围固定 2×2 到 10×10。

### 3.4 右栏：统计与入口

1. 顶部是大号游戏时间，等宽数字，是整个右栏的视觉重点。
2. 下面依次展示：
   - 移动步数；
   - TPS；
   - ao5；
   - ao12。
3. 统计数据使用两列布局：标签左对齐、数值右对齐；整块宽度与时间一致，右边缘与上方时间对齐。
4. 统计下方放两个入口，整体左对齐：
   - 列表按钮：跳转成绩页；
   - 当前分组按钮：显示当前事件的组名，点击弹出该事件的 5 个分组。
5. 右栏整体纵向居中；时间左对齐，统计标签左对齐、数值右对齐，统计块右边缘与时间对齐，入口保持左对齐。
6. 分组弹框从按钮上方展开，避免超出页面底部；顶部显示当前事件名（如 `3×3 普通`），下面从上往下排列该事件的 5 个组名，当前组高亮。
7. 重玩时隐藏 ao5/ao12，在 TPS 与入口行之间显示退出图标和“重玩中”标签；状态行与入口行的间距采用左栏按钮行间距。
8. 分组在 `observing` 和 `solved` 阶段可切换；`running` / 重玩 / 保存中禁用，已打开的分组弹框随之关闭。`solved` 阶段切换只影响下一局分组，不修改已完成成绩。

### 3.5 弹框交互

| 触发按钮 | 弹框内容                                   | 位置           |
| -------- | ------------------------------------------ | -------------- |
| 阶数     | 2 列 × 5 行，按钮显示 2～10 共 9 个，最后空一格 | 按钮右侧       |
| 游戏模式 | 普通 / 盲玩                                | 按钮右侧       |
| 操作模式 | 点击 / 滑动 / 键盘                          | 按钮右侧       |
| 分组     | 顶部显示当前事件名，下面列出该事件的 5 个固定分组名称 | 按钮上方       |

共同规则：

- 同一时间只打开一个弹框。
- 点击弹框外部或按 `Escape` 关闭。
- 当前选中项使用主题蓝底 `#3498DB` + 白字高亮。
- 弹框使用圆角、细边框和小尾巴，视觉上像聊天气泡。
- 设置按钮不在此列；它跳转独立设置页。

### 3.6 控件清单

| 控件       | 类型          | 归属任务 | 说明                                   |
| ---------- | ------------- | -------- | -------------------------------------- |
| 阶数       | 图标按钮      | P8-2     | 弹框 2×5；图标为 `#icon-size`           |

| 步数       | 文本          | P8-2     | 一次整行滑动按多步计数                 |
| TPS        | 文本          | P8-2     | 两位小数                               |

## 4. 视觉基调

### 4.1 整体

- 页面背景使用中性浅灰 `#ebebeb`，按钮使用略亮的 `#f8f8f8`；所有颜色集中在 `layout-lab.css` 的 `body.lab` 变量里。
- 页面主色以深灰/墨色文字为主，不额外引入高饱和品牌色；颜色主要来自棋盘主题。
- 不使用渐变、玻璃模糊、大面积卡片阴影。
- 棋盘不套底板或边框；按钮使用细边框、顶部白色高光和轻阴影建立层级，弹框使用轻阴影，但不能形成厚重的“悬浮卡片”效果。
- 按钮按下时整体向中心缩小到 `0.96`，阴影同步收紧，不使用位移和硬底边。

### 4.2 字体与数字

- 页面文字使用 `base.css` 的系统字体栈。
- 时间、阶数、步数、TPS、ao5、ao12、分组编号使用 `--font-mono`，保持数字等宽。
- 右栏时间字号最大；左栏阶数字号至少与时间同级，保持显眼。
- 右栏统计数据标签约 1.15rem、数值约 1.5rem，明显大于早期版本。
- 统计使用两列布局：标签左对齐、数值右对齐；同一行按文字基线对齐，整块宽度与时间一致，右边缘与时间对齐。
- 标签列保留约 0.25rem 的光学校正，抵消等宽数字左侧留白，让“步数”等文字的左缘与时间数字视觉对齐。
- 左右两栏整体字号要比早期版本更大，填满棋盘两侧的纵向空间。
- 不使用超大网页标题；页面不设置额外的大标题，让棋盘和计时获得注意力。

### 4.3 按钮

按钮规范：

```css
/* 示意，不是最终类名 */
.button {
  border: 1px solid var(--button-line);
  border-radius: 11px;
  background: var(--button-face);
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / 0.95),
    0 2px 4px rgb(0 0 0 / 0.08),
    0 1px 1px rgb(0 0 0 / 0.04);
  transition:
    transform 90ms ease,
    box-shadow 90ms ease,
    background-color 120ms ease;
}

.button:active {
  transform: scale(0.96);
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / 0.85),
    0 1px 2px rgb(0 0 0 / 0.06);
}
```

要求：

- 浅灰固体面，不使用任何渐变。
- 1px 浅灰边框 + 顶部 1px 白色内高光。
- 两层轻阴影，不做硬底边；按下时整体缩小，阴影收紧。
- 小圆角，约 11px。
- 默认只用图标，左栏方形按钮约 56×56px；右栏入口按钮约 50×50px。
- 左栏按钮分两行：第一行 3 个，第二行 2 个并靠右。
- 阶数弹框中的选项只显示数字 `2`～`10`，完整阶数由 `aria-label` 和顶部 N×N 文本表达。
- 必须有 `:focus-visible` 轮廓。
- 选中态使用深色底 + 浅色文字，不额外增加描边。
- 棋盘下方的刷新按钮是例外：透明底、无边框、无阴影，图标约 34px；悬停显示浅灰圆底，按下 `scale(0.92)`。

### 4.4 弹框

- 圆角约 14px，纯色背景，细边框。
- 使用一个 10px 的小尾巴指向触发按钮，形成聊天气泡感。
- 选中项使用深色底 + 浅色文字；未选中项悬停使用浅色底。
- 阶数弹框宽度约 9rem；分组弹框约 14rem；选项字号约 0.95rem。
- 分组列表最多显示全部 5 组；超出视口时内部滚动。

## 6. 响应式与可访问性

- 本轮只保证桌面端；窄屏和移动端在 P8-5 处理。
- 桌面端优先保证一屏内完成主要操作，不出现横向滚动。
- 所有图标按钮必须有 `aria-label` 和 `title`；图标本身 `aria-hidden="true"`。
- 弹框触发按钮使用 `aria-haspopup` 和 `aria-expanded`。
- 弹框选项使用 `aria-pressed` 表示当前选择。
- 弹框支持鼠标、键盘打开，`Escape` 关闭；关闭后焦点回到触发按钮。
- 棋盘 tiles 使用可读的 `aria-label`；盲玩时不能把数字写进无障碍标签。
- 运行中禁止打开设置页；设置页是独立页面，进入会离开当前局；左栏参数弹框允许切换，但会丢弃当前局并重新开局（P8-2 起）。
- 尊重 `prefers-reduced-motion`。
