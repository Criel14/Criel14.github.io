# 数字华容道成绩页与分组管理设计

> 状态：设计确认（2026-10-24）；P9 待开始
>
> 分支：`refactor/vite-ts`
>
> 配套文档：`docs/PUZZLE_ARCHITECTURE.md`、`docs/PUZZLE_STORAGE.md`、`docs/PUZZLE_GAME_PAGE.md`、`docs/PUZZLE_TASKS.md`
>
> 说明：本文负责成绩页（P9）的界面、分组管理流程、URL 状态和任务拆分；分组的数据模型以 `PUZZLE_ARCHITECTURE.md` 为准，索引、存储格式和容量估算以 `PUZZLE_STORAGE.md` 为准。

## 0. 背景与目标

P8 完成后，游戏页已经能打乱、计时、保存成绩与录像、重玩同一打乱。P9 要把成绩页从占位页替换为正式页面，并补上分组管理。

本轮要解决的问题：

- 分组从“全局 10 组”改为“事件级固定 5 组”。事件指 `阶数 + 游戏模式`，共 18 个；总计最多 90 个分组。
- 成绩页按“事件 → 分组”二级筛选，不再把阶数、模式和分组拆成互不相关的三个控件。
- 分组可以改名，但不能新增、删除或排序；改名不影响已保存成绩。
- 分组管理集中在成绩页，游戏页只负责切换；设置面板 P8-4b 主要处理外观。
- 成绩页展示统计、列表、高亮、详情和图表；删除/清空后局部刷新，不整页 reload。

非目标：

- 不做多标签页实时同步；刷新后看到其他标签页的修改即可。
- 不做分组导入/导出、分组排序、分组增删。
- 不做跨设备同步。
- P9 不实现设置面板和外观编辑器。

## 1. 分组模型摘要

| 术语 | 含义 |
| --- | --- |
| 事件 Event | `size + gameMode`；`size` 为 2–10，`gameMode` 为 `normal` / `blind`，共 18 个 |
| 分组 Group | 某个事件下的一组成绩；固定 5 个槽位，共 90 个 |
| 分组编号 `groupId` | 事件内槽位 1–5，不是全局唯一编号 |
| 成绩桶 Bucket | `size + gameMode + groupId` |
| 当前分组 | `GameSettings.groupId`，只存槽位 1–5，跨事件共享 |

关键约束：

- `moveMode` 不参与分组和成绩桶。
- 分组身份由 `size + gameMode + groupId` 共同确定；只存 `groupId` 不会丢失事件信息，因为成绩和筛选条件里都已经有 `size` / `gameMode`。
- 每个事件固定 5 个分组，不新增、不删除、不排序；只允许修改 `name`。
- `GameSettings.groups` 固定包含 90 项：9 种阶数 × 2 种游戏模式 × 5 个槽位。
- 默认名称：`分组1`～`分组5`。
- 当前槽位在事件之间共享：从 3×3 普通切到 4×4 盲玩时，仍然停留在槽位 1–5 中的同一个编号，名称按新事件解析。

### 1.1 默认名与显示名

存储的是短名，显示时再拼接事件上下文：

```text
存储名：分组1
游戏页分组弹框：顶部 `3×3 普通`，选项 `分组1`
成绩页筛选行：3×3 普通 · 分组1
设置/导出等全局场景：3×3 普通 · 分组1
```

规则：

- 默认名当前固定为中文 `分组1`～`分组5`。
- `TODO(i18n)`：接入语言检测后，非中文环境默认使用 `Group1`～`Group5`；已有名称不自动翻译。
- 名称 `trim()` 后不能为空，最长 30 字符；允许重名。
- 游戏页按钮和选项显示短名即可，`title` / `aria-label` 使用完整显示名。
- 成绩页的分组下拉显示短名；页面标题或统计区显示完整名。

### 1.2 数据与兼容

- localStorage 键名继续使用 `puzzle.v2.settings` / `puzzle.v2.appearance`；envelope `version` 升到 3。
- IndexedDB 数据库名继续使用 `puzzle.v2`；`DB_VERSION` 升到 2。
- v2 尚未上线，不做旧分组数据迁移；开发环境清空缓存即可。
- `ScoreRecord.groupId` 仍为 `1–5` 的数字；成绩的 `size` / `gameMode` 提供事件上下文。
- 分组不会删除，因此不存在“分组引用失效”；清空分组只删除成绩和录像，保留分组和名称。

## 2. 分组管理

### 2.1 入口

- 主要入口：成绩页筛选行右侧的“管理分组”按钮。
- 游戏页分组弹框只负责切换当前分组，不提供重命名。
- P8-4b 设置面板可以放一个跳转链接，但不在设置面板里再实现一套分组管理。

原因：

- 分组管理需要同时看到事件和 5 个名称，放在成绩页的筛选上下文里最自然。
- 游戏页进行中需要锁定分组，管理入口放在这里会增加状态复杂度。
- 避免同一功能在游戏页、成绩页、设置页三处重复。

### 2.2 重命名

打开对话框，标题显示当前事件，例如“管理分组 · 3×3 普通”。

内容：

- 5 行输入框，分别对应槽位 1–5。
- 输入框左侧显示槽位编号，右侧显示当前名称；不提供增删按钮。
- 允许重名；`trim()` 后为空视为非法，最长 30 字符。
- “保存”写入 settings；“取消”放弃本次修改。
- 保存失败使用现有非阻塞存储提示，对话框保持打开，允许重试。
- 保存成功后更新成绩页当前分组下拉、列表标题和统计区事件标题；不影响成绩、桶和 URL。

不建议实时保存每个输入：

- 5 个输入一起编辑，显式保存更符合“分组管理”这个低频操作。
- 避免每输入一个字符就写 localStorage，也避免取消后无法回滚。

### 2.3 清空

提供三个层级的清空操作，全部使用原生确认框，并显示待删除数量：

| 操作 | 范围 | 计数 API | 删除 API |
| --- | --- | --- | --- |
| 清空当前分组 | 当前 `size + gameMode + groupId` | `countScoresByBucket(filter)` | `clearScoresByBucket(filter)` |
| 清空当前事件 | 当前 `size + gameMode` 下 5 个分组 | `countScoresByEvent(size, gameMode)` | `clearScoresByEvent(size, gameMode)` |
| 清空全部 | 所有事件、所有分组 | `countAllScores()` | `clearAllScores()` |

规则：

- 只删除成绩和对应录像，不删除分组、不修改分组名称。
- 删除在同一个 IndexedDB 事务中完成，不能留下孤立录像。
- 清空后局部更新统计、列表、图表和分组下拉；不 `location.reload()`。
- 如果当前详情中的成绩被删除，关闭详情并清理 URL 中的 `score`。
- 清空当前分组后，该分组仍然存在，仍显示在 5 个槽位中。
- 删除单条成绩仍走详情页；删除后编号、统计、图表立即更新。

### 2.4 锁定规则

- 游戏页运行中、重玩中、保存中禁用分组切换；完成后保存结束可切换下一局分组；成绩页管理不受游戏页状态影响。
- 成绩页正在加载统计或保存分组名称时，禁用“保存”和清空按钮，避免重复操作。
- 不做多标签页同步；另一个标签页改名后，本页刷新才能看到。

## 3. 成绩页信息架构

### 3.1 顶部筛选行

桌面端从左到右：

```text
[事件：3×3 普通 v] [分组：分组1 v] [管理分组]        [清空当前分组] [清空事件] [清空全部]
```

- 第一级是事件下拉，共 18 项，按阶数分组显示：

  ```text
  2×2
    普通
    盲玩
  3×3
    普通
    盲玩
  ...
  10×10
    普通
    盲玩
  ```

  可以使用原生 `<select>` + `<optgroup>`；标签显示为 `2×2 普通`、`2×2 盲玩`。
- 第二级是分组下拉，只列当前事件的 5 个分组，显示短名；当前项高亮。
- 切换事件时：
  - 分组回退到 1，或保留当前槽位（如果该槽位存在）；
  - 使用 `history.pushState` 更新 URL；
  - 异步查询新桶，旧请求结果用请求序号丢弃。
- “管理分组”打开 2.2 的重命名对话框。
- 清空按钮按 2.3 的层级工作；数量为 0 时禁用或提示“没有可清空的成绩”。

### 3.2 统计区

显示当前桶的聚合值，全部来自 `computeScoreStats`：

- 成绩数。
- 最佳时间、平均时间。
- 最佳步数、平均步数。
- 最佳 TPS、平均 TPS。
- 最佳 ao5、最佳 ao12。
- 平均观察时间。
- 空桶时显示空状态，不显示 `0.00` 冒充有效成绩。

格式统一使用 `ui/format.ts` 的 `formatDuration` / `formatTps`；单位为毫秒。

### 3.3 成绩列表

列建议：

- 编号：桶内按 `finishedAt` 升序，编号从 1 开始，由 `assignNumbers` 派生。
- 时间、步数、TPS、观察时间。
- ao5、ao12：只对当前行及之后的窗口计算；无有效值显示 `—`。
- 完成日期：本地时区。
- 操作：查看详情、打开回放、删除。

高亮：

- 时间/步数/ao：最小最好、最大最差。
- TPS：最大最好、最小最差。
- 并列时全部标记。
- 高亮只做视觉提示，不改变排序。

排序：

- 默认按完成时间升序，和编号一致。
- 不提供多种排序，避免编号语义混乱。
- 删除后重新编号，不保留空洞。

空桶时显示“当前分组还没有成绩”，并提供返回游戏页的入口。

### 3.4 详情

- URL：`?size=3&mode=normal&group=1&score=<id>`。
- 使用原生 `<dialog>`；打开/关闭同步 `score` 参数。
- 内容：
  - 打乱缩略图（只读 board-view）。
  - 时间、观察时间、步数、TPS、曼哈顿距离、完成日期。
  - 大小、游戏模式、操作模式、分组完整名。
  - “打开回放”链接到 `/puzzle-game/replay.html?score=<id>`。
  - “删除成绩”按钮。
- 成绩不存在、已删除或数据损坏：关闭详情，清理 URL 中的 `score`，显示提示。
- 删除单条后：关闭详情、清理 URL、刷新当前桶统计/列表/图表。
- 回放缺失不影响成绩详情；只有打开回放时才提示录像不可用。

### 3.5 图表

- 使用 `buildChartSeries(scores)` 提供 `labels` / `timeSeconds` / `steps`。
- ECharts 懒加载，只在成绩页需要时导入；游戏页不加载图表库。
- 双轴：时间（秒）+ 步数；x 轴为派生编号。
- 0 条或 1 条成绩时隐藏图表，显示空状态/单条提示。
- 切换事件/分组时更新数据；不重复初始化图表实例。
- 窗口 resize 更新尺寸；页面销毁时 `dispose()`。
- 图表不展示录像，不加载 moves。

### 3.6 加载、空状态与错误

- 初次加载：显示加载状态；筛选行可以先渲染。
- 查询中：保留旧列表或显示轻量 loading，不让页面跳动过大。
- 空桶：显示空状态和返回游戏页入口。
- IndexedDB 不可用：显示非阻塞/可重试错误，筛选行仍可用。
- 查询失败：保留筛选条件，显示错误提示；不要回退到假数据。
- 快速切换事件/分组：使用请求序号或取消标记，只应用最新请求的结果。

## 4. URL 与页面状态

```text
/puzzle-game/score-list.html?size=3&mode=normal&group=1
/puzzle-game/score-list.html?size=3&mode=normal&group=1&score=<id>
```

规则：

- `size`：2–10；非法回退 settings 中的当前阶数。
- `mode`：`normal` / `blind`；非法回退 `normal`。
- `group`：1–5；非法回退 `settings.groupId`，settings 也异常时回退 1。
- `score`：详情成绩 ID；不存在时清理参数并提示。
- 筛选变化用 `history.pushState`；浏览器前进/后退监听 `popstate` 恢复。
- 分享链接应能恢复事件、分组和详情。
- 分组名称不进入 URL，避免改名后链接失效；URL 只使用槽位编号。
- 刷新后从 URL 恢复筛选；没有 URL 参数时使用 settings 中的当前事件和槽位。

## 5. P9 任务拆分

> 详细设计以本文为准；`docs/PUZZLE_TASKS.md` 只保留任务索引和状态。

### P9-1 页面骨架与事件/分组筛选

- 文件：`puzzle-game/score-list.html`、`src/games/puzzle/pages/stats.ts`、`src/games/puzzle/styles/stats.css`
- 内容：
  - 替换占位页，保留原 URL。
  - 渲染事件下拉（18 项，按阶数分组）和分组下拉（当前事件 5 项）。
  - 解析/写入 `size` / `mode` / `group`；`pushState` + `popstate`。
  - 从 settings 读取默认事件和槽位。
  - 筛选切换异步查询，使用请求序号忽略过期结果。
- 验收：刷新、分享、前进后退都能恢复筛选；快速切换不出现旧结果覆盖。

### P9-2 统计与列表

- 文件：`pages/stats.ts`
- 内容：
  - `listScoresByBucket(filter)` 只加载当前桶。
  - 统计区、列表、高亮、空状态、加载状态。
  - 编号由 `assignNumbers` 派生；分组名显示 `Group.name`。
- 验收：数字与纯函数一致；空桶显示空状态；加载失败显示错误提示。

### P9-3 详情、删除与分组管理

- 文件：`pages/stats.ts`、`ui/dialog.ts`
- 内容：
  - `?score=<id>` 打开详情；显示打乱缩略图、时间、观察、曼哈顿距离、步数、TPS、日期等。
  - 删除单条：`removeScore(id)`；更新当前桶。
  - 清空当前分组：`countScoresByBucket` + `clearScoresByBucket`。
  - 清空当前事件：`countScoresByEvent` + `clearScoresByEvent`。
  - 清空全部：`countAllScores` + `clearAllScores`。
  - 管理分组对话框：当前事件 5 个名称，显式保存。
  - 删除/清空后清理失效的 `score` 参数，不整页 reload。
- 验收：删除后编号/统计/图表立即更新；清空分组保留名称；清空事件不影响其他事件；无孤立录像；分组改名刷新后仍在。

### P9-4 折线图

- 文件：`pages/stats.ts`、`ui/chart.ts`（按需）
- 内容：
  - 懒加载 ECharts。
  - 时间 + 步数双轴；数据来自 `buildChartSeries`。
  - 0/1 条成绩隐藏图表；resize 更新；销毁时 dispose。
- 验收：图表按需加载；切换筛选不重复初始化；无内存泄漏警告。

### P9-5 成绩页 E2E

- 文件：`tests/e2e/stats.spec.ts`
- 内容：
  - 事件/分组筛选、详情、删除、分组改名、清空当前分组/事件/全部。
  - 刷新、URL 分享、浏览器后退。
  - IndexedDB 持久化：刷新后成绩仍在，删除后录像不存在。
  - 图表出现/隐藏。
- 验收：Playwright 通过；用户手动验收。

依赖：P9-3、P9-4；P9-5 需要先补 Playwright 基础设施。

## 6. 验收清单

- [ ] 事件下拉包含 18 个事件，分组下拉只显示当前事件的 5 个分组。
